# Standalone Core ML diarization benchmarks

See [measured results](RESULTS.md) for the comparison and its limits.

Two executables compare local model loading and processing. They do not integrate with the app. Generated silence checks framing and finalization. The same locally generated speech fixture exercises speech processing. Neither fixture establishes diarization accuracy.

## Pinned inputs

FluidAudio v0.17.4 is pinned to `21493f8dac5a97e65742e6ff26f42f164c2fda0f`.

| `NemotronBenchmark` | `FluidInference/nemotron-3-diarization-coreml@25a90f97f254428d4b30374b76af9c74fdee8327` | Monolithic v2 `.low` and silence embedding; 199,124,357 bytes | Native streaming; eight speaker slots |
| `Community1Benchmark` | `FluidInference/speaker-diarization-coreml@df2625ac79a7ac6b65ad868fee6d80f320da4232` | Segmentation, FBank, Embedding, PldaRho and PLDA parameters; 21,599,417 bytes | Offline segmentation, embeddings and VBx clustering |

Nemotron `.low` requires 1.04 seconds of input before a complete model window, excluding frontend context and processing. The smaller split-graph W8A8 models have a shortest published input window of 2.88 seconds and are not downloaded here. Community-1 is distinct from the legacy online Pyannote/WeSpeaker artifacts retained in its repository.

Both use Core ML `.all`, except Community-1 FBank uses `.cpuOnly`, matching its upstream loader. These settings permit device selection; they do not prove Neural Engine utilization.

## Build and fetch

Use Swift 6.2 or later on macOS. `traits: []` disables the Rust text-processing feature. SwiftPM 6.4 still downloaded its binary artifact during resolution; runtime and symbol checks distinguish downloading from linking. FluidAudio's full Swift library and C/C++ helpers compile because it has no separate diarization product. The app package is unchanged.

From this directory:

```sh
mkdir -p .cache results
CLANG_MODULE_CACHE_PATH="$PWD/.cache/clang" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.cache/swift" \
nice -n 10 xcrun swift build -c release --jobs 2 --disable-sandbox \
  --cache-path "$PWD/.cache/swiftpm" \
  --config-path "$PWD/.cache/config" \
  --security-path "$PWD/.cache/security"

UV_CACHE_DIR="$PWD/.cache/uv" uv run --no-project download_model.py nemotron
UV_CACHE_DIR="$PWD/.cache/uv" uv run --no-project download_model.py community1
```

Each downloader command fetches only the selected assets at an immutable snapshot, verifies object hashes and sizes, and writes a local manifest. Fetching is separate from compilation and execution. Executables load local Core ML models directly; missing files produce an error, not a download. Models, caches, generated audio and raw results are ignored by Git.

```sh
nice -n 10 /usr/bin/time -l .build/release/NemotronBenchmark "$PWD/.models/low" \

./generate_fixture.sh
nice -n 10 /usr/bin/time -l .build/release/NemotronBenchmark \
  "$PWD/.models/low" "$PWD/.fixtures/generated-speech.wav" \
  > results/nemotron-speech.jsonl 2> results/nemotron-speech.log
nice -n 10 /usr/bin/time -l .build/release/Community1Benchmark \
  "$PWD/.models/community1" "$PWD/.fixtures/generated-speech.wav" \
  > results/community1-speech.jsonl 2> results/community1-speech.log
```

The fixture script uses the locally installed Samantha system voice and generic text. It does not install voices. Keep the same generated WAV for both commands; voice versions can change generated bytes across Macs.

Nemotron runs five seconds of silence for warmup, sixty seconds paced in 20 ms blocks, then up to an hour accelerated. The accelerated silence phase stops after 180 wall seconds. Community-1 processes five, sixty and three hundred seconds of silence offline. It may return `no_speech_detected` before embedding and clustering, so silence speeds are not comparable. Each speech command runs the same fixture twice, reporting the first and warmed runs separately.

## File and replay modes

Both executables accept:

```text
Executable MODEL_DIRECTORY --audio PREPARED_WAV --mode offline|replay
  [--paced] [--max-seconds SECONDS] [--offset-seconds SECONDS]
  [--wall-limit-seconds SECONDS] [--segments-output PRIVATE_JSONL]
```

Interval exports contain model speaker IDs and timestamps, never transcript text. Keep them outside Git. Nemotron intervals use a raw 0.5 probability threshold with no smoothing and are marked provisional. Community-1 replay exports window boundaries because IDs are local to each recomputation.

Use prepared 16 kHz mono audio. `--paced` applies only to replay. Without a maximum duration, the entire remaining file is processed. Offset and maximum duration make a representative paced excerpt explicit.

- Nemotron uses its native stateful 20 ms chunk interface for both saved-file processing and replay. Saved-file mode runs it as fast as possible; it still uses `.low`, not the separately exported `.offline` preset. Audio buffers and outputs are discarded after measurement.
- Community-1 offline mode clusters the whole file. Replay recomputes a trailing thirty-second offline window every ten seconds, using only audio available by that update. Speaker IDs may change between windows. This is windowed recomputation, not native streaming or persistent speaker tracking.

The private runner reads an externally prepared manifest, verifies the selected input hash, and requires an output directory outside the worktree or under its ignored `tmp/` directory. Each run has an immutable attempt directory. Its receipt records the executable, input and model hashes, runner version, options, and output hashes; only an exact verified match is reused:

```sh
UV_CACHE_DIR="$PWD/.cache/uv" uv run --no-project run_private.py \
  --manifest "$PRIVATE_MANIFEST" --output-directory "$PRIVATE_RESULTS" \
  --sample C --model nemotron --mode offline --wall-limit-seconds 900
```

Run the same sample with `--model community1`, then replay with each model. Use `--mode replay --paced --max-seconds 60` for a bounded paced check. If the manifest provides `referencePath` or companion `reference-intervals/sample-X.json` metadata is present and no offset is supplied, the runner selects a ten-second-grid excerpt by existing-label diversity (at least two annotated seconds per label), then annotated coverage. This is a reproducible selection rule, not proof that the annotations or excerpt are representative. The selected offset is recorded, and both models receive the same excerpt. Both replay adapters advance availability in 20 ms steps. `run_suite.py` accepts the same manifest and output-directory arguments and runs both models serially across samples C, A, B and D in saved-file mode, Community-1 across all four in accelerated windowed replay, and both models on sixty-second paced excerpts from C and D; it resumes completed runs with interval exports. Nemotron saved-file mode already is full chronological accelerated native replay, so the suite does not repeat identical inference under another mode label. Never put private paths, source metadata, audio, transcripts or raw results in tracked files. Existing speaker labels are not ground truth.

## Metrics and limits

JSON lines report load time, processing time, first output where applicable, output counts and peak resident memory. The first Nemotron output is a probability chunk, not a confirmed stable speaker label. The first Community-1 replay output is a recomputed window, not a persistent identity. No stable-label latency metric is asserted.

Nemotron reports inference-call percentiles separately from calls between model windows. Per-output timing records scheduled arrival, processing start, output availability, and simulated backlog. Final summaries include maximum and p95 delay; model loading is outside the replay clock. First output is not a stable speaker-label latency measurement. Results validate finite probabilities, centered frame counts and idempotent finish. The pinned frontend uses `1 + (N + 512 - 400) / 160` frames for nonempty input; five seconds yields 501 frames. Sample duration, frame-grid span and nominal frame-bin duration are separate measurements. Future transcript alignment must clip the padded tail to the source duration.

Peak RSS is a cumulative process high-water mark, not instantaneous allocation ownership or the separate physical-footprint metric printed by `time -l`. Runs check a 2 GiB peak-RSS limit between processing steps. The private runner enforces an outer timeout, including model loading. Community-1 offline work cannot be interrupted by the harness between its internal stages; the outer timeout bounds that case. The synthetic Nemotron harness retains timing samples for its bounded run.

Resource limits yield partial results explicitly. Do not describe partial runs as full-file success. Cross-model timings must use the same audio and account for overlapping Community-1 windows. No result here proves accuracy, Intel support, minimum macOS behavior, battery cost, or performance alongside Apple Speech transcription.

## Compare saved speaker annotations

Use `compare_reference.py` on full-file segment exports and private reference JSON containing `audioDurationSeconds` and `intervals` (`start`, `end`, `speaker`). Keep reference labels scoped to their source track unless identity merging has been independently verified.

```sh
uv run --no-project python -B compare_reference.py \
  --reference "$PRIVATE_REFERENCE" --segments "$PRIVATE_SEGMENTS" \
  --output "$PRIVATE_COMPARISON"
uv run --no-project python -B tests/test_reference.py
```

The scorer integrates exact interval boundaries and finds the maximum-duration one-to-one speaker mapping. It reports missed, extra, and confused speaker-seconds divided by reference speaker-seconds. Its four views combine zero or ±250 ms boundary exclusions with included or excluded reference overlap. Matching is recomputed for each view. Duplicate intervals for one speaker count once. Unannotated gaps are unknown and excluded; predicted speech there is reported separately without calling it a false alarm. Scores can exceed 100% when many extra speakers are predicted.

This measures disagreement with saved annotations, not human-verified accuracy. Transcript segment boundaries may include pauses or omit speech. Inspect source duration, timeline alignment, provider provenance, and known recognition quality before comparing scores. The output includes artifact hashes and candidate disagreement intervals for private listening. Window replay exports are rejected: scoring those requires an explicit per-update identity and availability policy.

## Review whether a model improves on the server

See [the evaluation procedure](EVALUATION.md). Generate a private listening set from a prepared WAV, saved reference intervals, and both full-file model exports:

```sh
uv run --no-project python -B build_review.py \
  --audio "$PRIVATE_AUDIO" --reference "$PRIVATE_REFERENCE" \
  --model "$PRIVATE_FIRST_MODEL" --model "$PRIVATE_SECOND_MODEL" \
  --output "$PRIVATE_REVIEW_DIRECTORY" --seed 20261001
```

Listen to the WAV files in `blind/` and complete `blind/annotations.json` without opening `private/key.json`. Keep anonymous speaker IDs consistent across clips from the same recording. Record checked speech and silence through `reviewedRegions`; leave uncertain regions out. Empty templates are not annotations. The private key contains source coordinates and model predictions and must remain separate from the reviewer.

After review, export the independent sample and score all systems, including the saved server output:

```sh
uv run --no-project python -B build_review.py \
  --export-reviewed "$PRIVATE_REVIEW_DIRECTORY" --output "$PRIVATE_REVIEW_EXPORT"
uv run --no-project python -B score_review.py \
  --gold "$PRIVATE_REVIEW_EXPORT/gold.json" \
  --system server "$PRIVATE_REVIEW_EXPORT/system-00.json" \
  --system first "$PRIVATE_REVIEW_EXPORT/system-01.json" \
  --system second "$PRIVATE_REVIEW_EXPORT/system-02.json" \
  --output "$PRIVATE_REVIEW_SCORE"
```

Outputs must be new files or directories. Private outputs may be outside the checkout or under its Git-ignored, untracked `tmp/` directory. The exporter refuses unreviewed independent clips and excludes disagreement-selected diagnostics. No automatic model can establish this independent reference by agreeing with itself.
