## In progress (uncommitted when this was written)

Two sub-agents were still running. Their changes may be in the working tree without a commit. Check `git status`, run the checks below, and review each diff before committing.

1. **Recording CPU (about 90–108% while recording).** Profile evidence is `scratchpad/recording-sample.txt`, with the main thread extracted to `main.txt`. The main thread was busy in 7,662 of 7,672 samples, in SwiftUI graph updates and the display cycle. `LibraryView`, `MeetingDetailView`, `MeetingLanguagePicker` and `MeetingPlayerBar` are re-evaluated on every meter tick. Cause: high-frequency `@Published` recording state (levels, activity, elapsed time, health) on `MeetingStore`, which almost every view observes. Planned fix: move that state into a small `ObservableObject` that only the recording views observe, and remove per-buffer allocations in `TimedAudioWriter.convertLocked`. Target: under 20% CPU. Worklog: `2026-09-26-recording-cpu.md`.
2. **New Recording disabled during transcription.** Cause: the global `MeetingStore.isBusy`. Planned fix: track background jobs per meeting, and disable New Recording only while a recording is starting, running or saving, or when the library is read-only. Worklog: `2026-09-26-background-jobs-dont-block-recording.md`.

Both agents edit `MeetingStore.swift`. Commit them together if their changes interleave.
