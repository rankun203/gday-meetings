## Implemented solution

- Review and chooser contents use narrow observations behind stable view boundaries. Playback progress is observed by transport and timed highlighting consumers. Covered chooser presentation waits until the review sheet closes.
- Immutable presentation snapshots prepare references, recording labels, status and audio availability on a worker. Identical captured inputs reuse a cache. Playback revalidates audio asynchronously with unique selection tokens and the existing cancellation guard.
- Voice evidence is indexed by meeting. Projection caches are checked before audio reads and transcript scans. Relevant evidence revisions and filesystem events invalidate affected entries. Detached computations use captured inputs.
- Derived refresh requests coalesce by meeting. Results carry evidence revision tokens independent of cache eviction and revalidate the meeting and evidence inside the canonical mutation lane. A locally unavailable meeting is skipped. Saves target the affected meeting and restore still-owned state on failure. Confirm, Reject, Ignore, Name and Undo retain their serialized command path.
- Cold loading and launch refresh use asynchronous projection while preserving awaited persistence and save-failure behavior. File changes refresh affected loaded projections without requesting global suggestion matching. Review-driven matching requests survive coalescing, including arrival during an active filesystem refresh.
- Chooser search filters a prepared catalog without rereading metadata. Review loading validates captured displayed evidence and exact aliases. Unrelated metadata, index updates and new questions do not interrupt loading. Repeated displayed-evidence drift retains the current session or offers Try Again. Refreshed presentation retains decided rows and excludes their exact reference aliases.
- Fixed-name action signposts identify candidate loading, presentation preparation, projection and decision commits without recording private content.

## Reasoning

Caching and narrower observation remove redundant work before introducing concurrency. Worker publication checks preserve correctness when selection, metadata or evidence changes during preparation. Coalescing applies only to derived refresh requests.

Final preview validation exposed an extra whole-library matching request after filesystem notifications. That request cleared seeded named suggestions before review. The fix separates projection refresh from suggestion matching at the owning scheduler; regression tests cover both filesystem-only work and coalesced review requests. The corrected preview retains the expected named candidates at startup.

A failed canonical save intentionally stops its derived batch and restores owned projection state. Automatic rematching after that failure would introduce further writes after an error; retaining only matching intent would also omit failed or unprocessed meetings. A later explicitly requested review refresh uses the existing retry path.

## Technical debt

The synchronous projection entry point remains in RecordingPipeline, LiveTranscriptAdoption and CommunityDiarization, whose canonical mutation paths require coordinated commits. It shares per-meeting indexes and cache, but cache misses can still compute on the caller. Migrate each remaining caller with immutable input and a transaction-boundary revision check before publication. Cold loading and startup no longer use this compatibility path. No schema changes or automatic failure-retry infrastructure were introduced.
